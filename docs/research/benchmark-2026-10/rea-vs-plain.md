# Проход без REA и с REA: что изменилось
Дата: 2026-10-18. Инструмент: rea-agents 6.5.0 (запуск `npx rea-agents@6.5.0`, без регистрации в конфигах Claude). Эмулятор Android Pixel 6 (API 35) на Mac mini; приложения: Organic Maps 2026.09.29-32, OsmAnd 5.4.10, Google Maps 11.129.0103. Сырые выводы REA, снимки и контрольные суммы лежат на Mac mini: `~/ai-cloude-agents/claude/research/rea-pass/`.

Метка метода у каждого факта: «ПЛ» — проход без REA (прежние README в `../map-services`, `../organicmaps`, `../osmand`); «REA» — получено командой REA; «РУЧН» — обычные средства (adb, unzip, браузер) после подсказки REA. В аккаунты не входил, правки не отправлял, проверки на бота не обходил.

## 1. Что такое REA
- 153 команды (`rea --llms-full`). Группы: Android/adb ≈ 32; веб, браузер, Electron, JS ≈ 26; нативные бинарники (Hopper, Ghidra, IDA, Cutter, GDB, Rizin, objdump) ≈ 31; сеть и pcap ≈ 4; Apple/iOS ≈ 8; прочее (сравнение, трассировка, экспорт и импорт доказательств, отладка, Frida) ≈ 52.
- Каждая команда возвращает «доказательство»: evidence_id, провайдер, параметры, результат, ограничения. Снимки — PNG с SHA-256, выгруженные APK — тоже с SHA-256. Есть режим MCP (`rea mcp`) и навыки агентов (`rea setup`); они не включались, чтобы не менять конфиг Claude.
- `doctor`: не хватает Hopper, Ghidra, IDA и JAR jadx-headless-mcp 0.7.1 (REA его сам не ставит). apktool 3.0.3 работает. Ничего доустанавливать не стал.
- Из-за этого не работают inspect-android-package, search-android-classes, inspect-android-class, inspect-android-method (capability_unavailable): нет глубокой декомпиляции и поиска по коду.
- Ограничения, которые REA назвал сам: extract-artifact не извлёк APK Organic Maps на macOS (файлы res/-k.webp и res/-K.webp, файловая система не различает регистр); decode-android-resources отдаёт не больше 2000 строк на приложение (покрытие «partial»); capture-web-screenshot снимает только видимую область; inspect-web-page не видит сеть до подключения.

## 2. По сервисам

### Organic Maps (родное, APK с эмулятора)
- ПЛ: путь «Add Place → форма → вход» снят; вывод — нет типов про доступность.
- REA pull-adb-package: APK 63 797 784 байт, SHA-256 654a736d…07f8bc. REA inspect-artifact: 1997 файлов, 4 нативные библиотеки (liborganicmaps.so для arm64, armeabi, x86, x86_64), 2 dex, assets/editor.config. REA decode-android-resources: 21 экран (EditorActivity, FeatureCategoryActivity, OsmLoginActivity, ProfileActivity, BookmarkCategoriesActivity, DrivingOptionsActivity…), 13 разрешений, 57 локалей, 109 строк по правкам, спискам и OSM.
- РУЧН после REA: assets/editor.config — 385 редактируемых типов мест и 31 поле (имя, улица, дом, телефон, часы, сайт, email, кухня, интернет, соцсети…). Слов wheelchair, ramp, elevator, step, kerb в конфиге нет. Значит, доступности нет в форме по конфигурации приложения, а не по случайности интерфейса.
- REA не помог: логика отправки правок и классы (нужен JAR jadx MCP).

### OsmAnd (родное)
- ПЛ: путь с плагином OSM Editing; вывод — нет маршрута для коляски.
- REA decode-android-resources: строки app_mode_wheelchair = «Wheelchair», app_mode_wheelchair_forward = «Wheelchair forward», «Accessibility mode», empty_state_osm_edits.
- РУЧН проверка на эмуляторе: в Settings → App profiles (и при создании профиля) «Wheelchair» нет; есть Browse map, Driving, Cycling, Walking, Truck, Motorcycle, Moped, Public transport, Train, Boat, Aircraft, Skiing, Horseback riding. Строка в ресурсах есть, профиля в интерфейсе 5.4.10 нет. Это неподтверждённая подсказка REA; вывод по экранам остаётся верным.
- REA capture-adb-screen: кадр совпадает с кадром через adb.

### Google Maps (родное, системный APK эмулятора)
- ПЛ: карточка места без блока доступности; «Wheelchair accessible» только в настройках общественного транспорта.
- REA pull-adb-package: Maps.apk 85 153 770 байт, SHA-256 4589b9b8…c545. REA decode-android-resources: 89 экранов, 42 разрешения, 7 локалей.
- Идея своими словами: Google умеет хранить и показывать доступность входа, парковки, туалета и мест, а также маршрут без лестниц; у места в Сухуме эти данные просто не заполнены.
- Идея своими словами: у Google есть «двигатель вклада» — миссии, отчёт о проблеме, отзыв, вопросы после поездки, отметка «я тут не был», задания сфотографировать, вехи сообщества, лента местных гидов. Это приёмы побуждения к вкладу; без входа в аккаунт была видна только вкладка вклада.
- REA не помог: заполненность данных по Сухуму; что делают эти экраны (нужен код).

### Веб-версии через REA
CDP на 127.0.0.1:9222, профиль телефона, Chrome 155. Снимки на Mac mini в `rea-pass/web/`.
- Apple Maps (REA capture-web-screenshot): улицы подписаны («Улица Лакоба», «Проспект Аиааира», «Сухуми»). Это исправляет прежний вывод «подписей нет»: во встроенном браузере подписи, видимо, не успели загрузиться. Точек интереса на этом масштабе нет.
- Яндекс Карты: страница «Вы не робот?» (капча). Защита от ботов не обходилась; данные по Яндексу остаются из прохода без REA.
- 2ГИС: страница «2ГИС советует обновить браузер» с кнопкой «Пропустить»; содержимого Сухума нет. Выводы остаются из прохода без REA.
- Wheelmap: проверка Cloudflare «Подтвердите, что вы человек». Не обходилась.
- AccessNow (REA capture-web-screenshot, inspect-web-page, analyze-web-bundle): баннер приложения и «Filter»; 265 узлов DOM, 104 узла дерева доступности, один скрипт main.63703a54.js (4 164 841 байт), 0 сетевых запросов за окно наблюдения; распознан React (уверенность средняя), адрес ipinfo.io/ip. «Кандидаты в API» — в основном шум (уверенность низкая); адресов API AccessNow REA не показал.
- Вывод: сайты за защитой от ботов REA показывает как есть, поэтому для Яндекса, 2ГИС и Wheelmap пользы мало. Без защиты (Apple, AccessNow) даёт снимок с хэшем и структуру страницы.

## 3. Итог: без REA и с REA
- Что видно. Без REA — только то, что показывает интерфейс. С REA — плюс то, что приложение умеет, но не показало: строки, экраны из манифеста, конфиг редактора.
- Доказательность. Без REA — скриншоты. С REA — плюс SHA-256 APK и снимков, evidence_id, явные ограничения.
- Самые ценные находки: почему в Organic Maps нет доступности (editor.config); какие атрибуты доступности и «миссии» есть у Google; карта экранов обоих приложений.
- Поправки к прежнему: у Apple Maps подписи улиц есть; у OsmAnd строка «Wheelchair» в ресурсах есть, профиля в интерфейсе нет.
- Где слабее: без JAR jadx-MCP нет классов, методов и поиска по коду; строки ограничены 2000 на приложение; веб за защитой от ботов не открывается.

## 4. Что следует для GoApsny
1. В Organic Maps доступность не вводится из-за конфигурации: assets/editor.config, 385 типов и 31 поле без полей доступности. Поля добавляются правкой конфига, а не кода.
2. У Google в ресурсах уже есть модель атрибутов доступности: вход, парковка, туалет, места, с ответами «доступно / недоступно». Для Сухума не заполнены.
3. «Двигатель вклада» Google: миссии, вопросы после поездки, «не был здесь», фото-задания, вехи сообщества — перечень приёмов для нашей механики вклада.
4. Параметр маршрута «Avoiding stairs» есть у Google; у OsmAnd профиль коляски не подтверждён.

## 5. Почему REA ценят разработчики (по этому прогону, не по отзывам)
- Ничего не выполняет и не меняет; возвращает проверяемые факты с хэшами и честными ограничениями. Каждый факт можно воспроизвести.
- Один интерфейс и один язык вывода для APK, устройства (adb), веб-страницы и сети.
- Дал то, чего не было в обычном проходе: карту экранов, «что приложение умеет, но не показало» и конфиг редактора, который объяснил результат прохода.
- Сильнейшие команды (классы, методы, поиск по коду) требуют внешних движков: JAR jadx-MCP, Ghidra, Hopper. С ними разбор дошёл бы, например, до адреса, куда уходит правка.

## 6. Что не удалось
- Классы и методы приложений: нет JAR jadx-headless-mcp.
- Яндекс, 2ГИС, Wheelmap через REA: защита от ботов, не обходилась.
- Внутренние запросы приложений (HAR, pcap): перехват трафика не настраивался.
- Родные Яндекс, 2ГИС, Wheelmap, AccessNow: APK только в магазинах.
