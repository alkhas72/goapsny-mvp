## Решение, на котором стоит план

Алхас, 2026-11-08, тред «Приставные пандусы: производство». На вопрос «Где хранить заявки, аудиторов и заведения Stopgap?» он выбрал «В базе карты GoApsny». Страница решения: `ais-obsidian`, `wiki/00-Ҳазҭагылоу-аамҭа/decision-stopgap-data-goapsny-base-2026-11-08.md`.

По `AGENTS.md` контракт фронт↔бэк меняется только с согласия Алхаса. Согласие на перенос данных дано. Сама схема ниже ещё не утверждена.

Подробное описание для людей: док «Stopgap: какие данные копятся и жизнь заявки», https://claude.ai/artifact/EVfb8wQXGoF5aeYGU9Dm1P.

## Что уже есть в базе и что из этого берём

- `places` — единый список заведений (контрагентов) для карты и Stopgap. Новый список не заводим.
- `places.ramp_type` уже знает `portable_on_request` и `portable_available`.
- Новое заведение от участника без роли сборщика создаётся через существующий `submit_public_place`.
- `profiles` — роли и `telegram_id`; чужой профиль читают только сам владелец и admin/owner (`profiles_read_own_or_admin`).
- Вход через `auth-telegram`.
- `karma_events` — основа для благодарности и роста аудитора.

## Вход

Предлагаю открывать Stopgap как Mini App того же бота. Тогда работает уже существующий путь `auth-telegram` (Telegram `initData` → JWT), и это телефон, где проходит 90–95% замеров.

Вход из обычного браузера через Telegram Login Widget требует другой проверки подписи. Это отдельная работа, позже.

Версия в claude.ai остаётся демонстрационной.

## Схема (эскиз, не SQL миграции)

### `profiles` — новые колонки

| Колонка | Что хранит |
|---|---|
| `full_name text` | Имя и фамилия, вводятся один раз |
| `phone text` | Телефон |

Видимость не меняется: свой профиль видит владелец, все профили видят admin и owner. Анонимные заявки не принимаются, поэтому без `full_name` и `phone` отправка заявки отклоняется (проверяет RPC, см. ниже).

### `ramp_sites` — место установки

У одного заведения может быть несколько мест: вход, подиум, туалет.

| Колонка | Что хранит |
|---|---|

| `label text` | Например «главный вход», «подиум у сцены» |
| `created_by` | |
| `created_at` | |

### `ramp_requests` — заявка (замер)

| Колонка | Что хранит |
|---|---|

| Колонка | Что хранит |
|---|---|
| `id` | |

Первый осмотр — через 6 месяцев после установки, дальше раз в год. Срок предварительный, ждёт подтверждения Алхаса.

### Представление `auditor_stats`

Число заявок, установленных пандусов и перезамеров на аудитора.

Уровни (новичок, аудитор, опытный) считаются отсюда. Пороги задаёт Алхас; обсуждались 25–30 пандусов для видео в потоке.

## Статусы и переходы

| Из | В | Кто | Как |
|---|---|---|---|
| — | `draft` | автор | insert |
| `draft`, `remeasure` | `submitted` | автор | RPC `ramp_submit(request)`: проверяет 4 обязательных фото, числа, `full_name` и `phone` профиля |
| `submitted` | `accepted` / `remeasure` | admin, owner | RPC `ramp_set_status(request, to, reason)`; для `remeasure` `reason` обязателен |
| `accepted` | `production` → `ready` | admin, owner | то же |
| `ready` | `installed` | admin, owner | то же + `ramp_units.installed_*`; триггер ставит `places.ramp_type` (значение — вопрос 2) |
| `installed` | `service` | по дате | задача по расписанию по `ramp_inspections.due_at` |
| любой после `installed` | `removed` | admin, owner | |

Каждый переход пишет строку в `ramp_events`.

## Правила доступа (дополнение к `docs/rls-checklist.md`)

- Автор читает свои заявки, их фото, события и изделия. Admin и owner читают всё.
- Автор меняет заявку только в `draft` и `remeasure`. Статус меняется только через RPC.
- `banned` ничего не создаёт.
- `public_user` может создать заявку (Алхас: «любой человек может зарегистрироваться»). Новое заведение он заводит через `submit_public_place`.
- Публично, без входа, наружу уходит только `places.ramp_type`.
- Фото заявки на карту не попадают.
- `ramp_events` и `ramp_inspections` пишутся только из RPC и задач (security definer, `search_path` закреплён).
- Проверить по образцу 0001: RLS включена на всех новых таблицах, `anon` не имеет прав.

## Что меняется в Stopgap

- Шаг «Кто и где» сжимается до «Где»: заведение из списка рядом или новое.
- Профиль заполняется один раз.
- Появляются «Мои заявки» со статусами, полосой готовности и причиной перезамера.
- Отправка заявки идёт в новые таблицы и бакет вместо хранилища claude.ai.
